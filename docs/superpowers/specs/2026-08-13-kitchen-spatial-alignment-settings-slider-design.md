# 厨房空间关系与设置滑块修正设计

## 目标

修正当前实机中的三项视觉与交互问题，同时不改变已确认的人物、夜市场景、订单流程和烹饪规则：

1. 左侧食材必须像场景原生物件一样嵌入台面铁盒槽，不再以完整铁盒贴纸悬浮、倾斜或覆盖其他器具。
2. 每个制作阶段的饼必须以所属铁板内膛为中心显示，不能偏向铁板边缘或跨出有效烹饪区。
3. 设置页每条音量轨道只能出现一个真实可拖动滑块，清除底图中与 HTML 控件重叠的烘焙圆点。

## 已确认方案

### 1. 食材嵌入背景铁盒槽

- 第一天沿用背景左侧原生的 `2 × 3` 铁盒阵列。
- 交互按钮仍覆盖完整铁盒槽，保留点击、拖动、键盘操作及新手教程高亮。
- 视觉层不再直接显示带完整容器轮廓的大尺寸素材；运行时只显示经过裁切和透视校准的食材内容，使背景铁盒本身承担容器、边框、阴影和台面遮挡关系。
- 每种食材使用相同的槽位裁切窗口、统一的底部基线和透视缩放；食材不得越过铁盒内沿。
- 后续关卡新增食材继续限定在左侧台面区域。扩展阵列可以增加行列，但必须保持同一尺寸体系，不能越过左铁板边界或屏幕底部。
- 酱料仍是一项可识别的槽内素材，选中后进入刷酱手势；不得恢复悬浮 Unicode 刷子或独立方圆 UI。

### 2. 铁板和制作阶段美术锚定

- 左、右铁板分别定义唯一的“内膛有效矩形”，视觉渲染、拖放命中、手势层和教程箭头共享同一组坐标。
- 所有累计制作阶段美术采用 `50% / 50%` 中心锚点放入所属内膛，并使用 `object-fit: contain` 保持完整可见。
- 面皮、加蛋、加肠、刷酱、撒料、煎制、卷起和切段阶段均不得各自使用不同偏移。
- 制作阶段的最大可见范围需与铁板内沿保留安全边距，不能压住铁板金属边框、相邻铁板或左侧食材槽。
- 拖入面皮后的落点由铁板槽位决定，而不是使用指针松开时的自由坐标，因此无论从哪个方向拖入，饼都会落在铁板正中。

### 3. 设置页滑块去重

- 当前参考底图的三个音量轨道含有烘焙滑块位置，真实 HTML range 控件叠加后可能形成双圆点。
- 对三个轨道分别增加与面板纸张、轨道材质一致的局部干净遮罩，覆盖烘焙滑块但不改动标题、图标、标签或返回按钮。
- 遮罩上仅渲染真实 range 轨道与一个 thumb；三个滑块使用完全相同的结构和样式。
- 实际圆点位置必须与保存的总音量、背景音乐和音效数值一致，拖动、键盘调整、刷新后恢复及静音逻辑维持现状。

## 组件边界

- `KitchenScene` 负责槽位数量、解锁状态与交互路由，不承担食材图片的自由定位。
- `TableIngredient` 负责在既定槽位窗口内渲染食材内容和拖动幽灵图。
- `GriddleSlot`、`CookingGestureLayer` 和教程提示共同消费同一份铁板几何定义，避免视觉层与命中层再次漂移。
- 设置页继续使用原有音频状态模块；本次只调整视觉合成和控件呈现，不改变音量计算公式。

## 异常与兼容处理

- 未解锁食材不占可见槽位，也不留下空白交互按钮。
- 浏览器不支持 WebKit range 伪元素时，Firefox 样式仍保证单一 thumb。
- 在非 `1440 × 810` 窗口中继续使用现有整体等比缩放，内部槽位和铁板坐标不单独响应式变形。
- 拖动取消、指针离开或触摸中断后必须清除幽灵图，不能在台面留下悬浮素材。

## 验收标准

### 视觉验收

- 第一天5种已解锁食材均位于背景铁盒内，边缘不越出内沿，没有额外容器叠影。
- 第三天和第五天新增食材保持统一透视、基线和间距，且不与铁板、教程卡或屏幕边界重叠。
- 左右铁板放入面皮后，饼的可见中心与铁板内膛中心重合；所有后续累计阶段保持同一中心。
- 设置页三条轨道在最小值、中间值和最大值下，每条始终只出现一个圆形滑块。

### 交互验收

- 食材点击、鼠标拖动、触摸拖动和键盘操作仍能将正确食材送入正确铁板。
- 同时制作两份时，左右铁板的阶段美术和命中区互不干扰。
- 第一天刷酱仍只需两个左右笔画，向右滑一次仍能完成卷起。
- 三条音量滑块能拖动、键盘调整、持久化，并正确影响主音量、BGM 和音效。

### 自动化与实机验证

- 增加槽内裁切、铁板共享几何、制作阶段中心和滑块单圆点的回归测试。
- 在 Microsoft Edge `1440 × 810` 下检查第一天、第三天、第五天和设置页截图。
- 继续通过全部单元测试、美术清单验证和生产构建后才能发布。

## 非目标

- 不重画或替换顾客、订单气泡、夜市背景、铁板、菜单和关卡结算页。
- 不调整顾客耐心、烹饪等待时间、配方、关卡解锁或价格。
- 不新增设置项或改变音频文件。
