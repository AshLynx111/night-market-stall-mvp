# 夜市大排档完整视觉一致性 QA 设计

## 目标

对生产构建执行一次覆盖完整用户流程的视觉一致性审计，只修复 P0、P1 明显视觉问题。不得新增功能、修改玩法、调整页面结构，亦不得重新设计已经验收通过的游戏主界面和结算页。

## 审计方法

采用“真实流程截图 + DOM/交互状态检查 + 人工视觉复核”的混合方式：

- 使用 Edge 打开生产预览，从空存档开始真实完成 Day 1，并进入 Day 2。
- 每个关键状态分别以 1440×810 和 844×390 截图，确保桌面和手机横屏使用同一套真实业务状态。
- 额外以 390×844 捕获竖屏横屏提示，因为该提示按设计只在竖屏出现。
- 记录控制台异常、资源解码失败、视口越界、关键元素重叠、按钮 hover/active/disabled 状态、图标来源和可见文本。
- 对截图人工检查贴图感、2D/2.5D 冲突、描边/光照/尺寸、对比度、动态文字覆盖和跨页面按钮一致性。

## 截图矩阵

完整流程中的关键状态：

1. 首页
2. 选关
3. Day 1 教程
4. Day 1 多顾客 / 双铁板
5. Day 1 结算
6. 升级后的结算状态
7. Day 2 游戏状态
8. 设置页
9. 手机竖屏横屏提示（额外 390×844）

前八个状态均生成 1440×810 与 844×390 两张截图。截图和机器检查结果保存到 `docs/qa/screenshots/full-visual-consistency-v1/`。

## 严重程度

- **P0**：阻断流程、主要操作不可见或不可用、关键内容严重越界或被覆盖。
- **P1**：一眼可见的重叠/截断/低对比度、残留 emoji 或系统图标、明显独立贴图感、风格或交互状态突变、手机安全区错误。
- **P2**：不影响识别和操作的轻微间距、比例、色差或审美偏好。

只修改 P0/P1。P2 仅写入报告，不改代码。

## 修改边界

- 优先做局部 CSS、SVG 或可访问状态修正。
- 不改变卡片、按钮、场景或页面的布局结构。
- 不改变文案、数值、关卡、顾客、烹饪和升级逻辑。
- 已验收的主界面与结算页只有发现 P0/P1 时才允许做最小修复。
- 所有修改必须有针对性回归检查，并重跑完整截图矩阵。

## 交付物

- 每个关键页面的桌面与手机横屏 QA 截图，以及竖屏提示截图。
- `docs/qa/full-visual-consistency-v1.md` 审计报告。
- 报告表格字段固定为：`页面 / 问题 / 严重程度 / 是否已修复 / 修改文件`。
- 完整测试、生产构建和浏览器 QA 结果。
